# BGAD News Flash site

Static host for the daily News Flash HTML editions. Zero dependencies, Node 18+.

## Routes

| Path | What it serves |
| --- | --- |
| `/` and `/latest` | 302 redirect to the newest issue |
| `/issues/YYYY-MM-DD.html` | a specific issue (this is the URL to flip) |
| `/archive` | simple list of every published issue |
| `/archive.json` | the same list as JSON |
| `/health` | health check used by Railway |

Issues are just files in `public/issues/`, named `YYYY-MM-DD.html` so they sort correctly.

## Deploying to Railway

Option A, from your machine, no repo needed:

```
npm i -g @railway/cli
railway login
railway init        # creates the project, pick a name like bgad-newsflash
railway up          # deploys this folder
railway domain      # generates a public https://<name>.up.railway.app URL
```

Option B, GitHub connected. This folder is already a git repo with one commit,
branch `main`, and the remote set to
`https://github.com/gerdschenkel/bgad-newsflash.git`. Create that repo on
GitHub (empty, no README), then:

```
git push -u origin main
```

In Railway choose New Project, Deploy from GitHub repo, pick `bgad-newsflash`.
Railway detects Node from `package.json` and runs `npm start`. Click Settings,
Networking, Generate Domain. From then on every push redeploys the site.

A custom domain like `newsflash.bgadconsulting.com` can be added under
Settings, Networking, Custom Domain, then a CNAME at your DNS provider.

## Branding assets

Do not embed images as base64 data URIs. Earlier issues did, and it caused two
problems: the in-page banner was frozen at 400x221 so it looked soft, and
`og:image` was unusable, because link crawlers fetch that value over HTTP and
silently drop anything that is not a real URL. Flipboard cards rendered with no
image at all.

Assets now live as real files under `public/assets/` and are generated by
`tools/make_cover.py`:

| File | Size | Used for |
| --- | --- | --- |
| `assets/bgad-logo.png` | 110x53 | masthead logo |
| `assets/newsflash-banner.jpg` | 1600x884 | in-page banner, static, art only |
| `assets/covers/YYYY-MM-DD.png` | 1200x630 | `og:image`, dated, one per issue |

```
pip install --break-system-packages pillow
python3 tools/make_cover.py 2026-08-14     # or no argument for today, Sydney time
```

The card is a blue panel on the left carrying the masthead, title, subtitle and
date, with the brand artwork bleeding in from the right. Source artwork is
`tools/cover-source.png` at 1117x1117. To rebuild the in-page banner after
changing that file, pass `--force-banner`.

## Publishing a new issue

Build the issue from `tools/template.html`, which already has the correct head.
Generate the cover first, or `og:image` will point at a 404.

Drop the day's HTML into `public/issues/` named by date, then redeploy:

```
cp "BGAD News Flash 14 August 2026.html" public/issues/2026-08-14.html
railway up
```

Or, with the GitHub option, commit and push. Railway redeploys on push, so the
daily routine only has to commit one file.

## Flipboard

Flip `https://<your-domain>/issues/2026-08-13.html`, not `/latest`. A dated URL
is a stable permalink, so the card keeps showing the right issue.

Flipboard builds the card from three tags, so all three have to be right:

- `og:image`, an absolute https URL to a 1200x630 image that returns 200 to an
  anonymous request. This is the one that used to be missing.
- `og:title`, rendered as the card headline.
- `og:description`, rendered as the card body. Write it as a teaser that names
  three or four concrete stories and ends with an invitation to open the page,
  for example "Tap to read the full briefing". A generic standing subtitle gives
  readers no reason to click through, and the card looks like the whole item
  rather than a pointer to one.

Flipboard caches what it scraped the first time it saw a URL. If a card was
flipped before the tags were fixed, re-flipping the same URL can serve the stale
version, so check the card and remove and re-add it if it still looks wrong.

Cost note: this fits inside Railway's hobby usage. It is a single small Node
process serving static files, idle most of the day.
